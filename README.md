# 家計簿 v3

りそなデビットのメールを自動で取り込み、iPhoneのホーム画面から開ける家計簿。
すべて無料枠で動きます。

```
Gmail（りほ宛のりそなメール）
   ↓ Google Apps Script（1時間ごと／アプリの「りそなを読み込む」ボタン）
Supabase（PostgreSQL）
   ↓
Next.js アプリ（Vercel）→ iPhoneのホーム画面に追加
```

今の状態から最終版にする手順は **`やること.md`** にあります。

---

## 家計の考え方

**口座は共通りそな1つ。** 生活費と貯蓄を同じ口座に置き、アプリの上で分けて見せます。

```
25日  2人が拠出                     349,000（10月）／ 326,000（11月〜）
  ↓
同じ口座の中で
  生活費   249,000  家賃 135,000 ＋ 変動費 114,000（食費・外食・出前・日用品・光熱費・娯楽）
  貯蓄     残り全部 100,000（10月）／ 77,000（11月〜）← 口座から出さない
  ↓
翌月へ繰り越す。貯蓄分は積み上がっていく
```

- **毎月の貯蓄額は自動で決まります。** 拠出の合計 − 生活費の予算。設定で拠出や予算を変えれば、その月から貯蓄額も変わります
- **ボーナス・還付金**は貯蓄に入ります
- **旅行・住民税・誕生日などの年間支出**は貯蓄から出ます
- **個人口座のお金**（スマホ・美容室・お小遣い・奨学金・生命保険）はアプリの管理外です
- **運用資産**（個人年金・自社株・投資信託・NISA）は給与口座から引かれるもので、別タブで累計だけ出します。現金ではないので貯蓄には混ぜません

### 家計の1か月は「25日〜翌月24日」

カレンダーのマスは1日始まりですが、上のカードと合計は**25日〜翌月24日**で出します。
10月のカレンダーを開くと、今日が入っている期間（9/25〜10/24）が出ます。カード上の ‹ › で、その月にかかるもう1つの期間（10/25〜11/24）に切り替えられます。期間の外の日は薄く表示されます。

- **予算・拠出の「いつから」**は、選んだ月の25日から始まる期間に効きます（10月を選ぶと10/25〜）
- **25日に入れる額**は、その前の期間（9/25〜10/24など）の立替と、その月の誕生日分を差し引いた額です
- **家賃**は28日。土日祝なら翌営業日に記帳します（祝日は振替休日も含めて自動判定）

### 「使えるお金」

通帳の残高には貯蓄分が混ざっているので、そのままでは使っていい額が分かりません。
アプリでは、期間の締め（24日）までの予定も含めて差し引いた額を出します。**残高ではなくこの数字を見てください。**

変動費のバーの下には、期間が何%過ぎたかが出ます。予算を使うペースが早いと、このままだといくらオーバーするかを表示します。

### 通帳の残高と合わせる

カレンダーのいちばん下のボタンです。今の通帳の残高を入れると、アプリとの差を「残高調整」として記録します。
アプリを始める前のお金や、取り込めなかった入出金をまとめて埋めるためのものです。ずれが気になったときにいつでも使えます。

### 拠出から差し引くもの

本人が払った共通の支出は、その月の拠出から差し引きます。カレンダー下に「入れる額」として出ます。

- **立替**: デビットが使えない店で払った分。手入力で支払者を本人にする
- **誕生日プレゼント**: 自動。ゆうき→りほ（10/3）はゆうきが**8/25**、りほ→ゆうき（10/31）はりほが**9/25**の入金から10万円差し引く。手元に残した10万で買うので、中身は相手に見えません。2027年から（2026年分はアプリを始める前に済んでいる）

## 画面

| タブ | 内容 |
|---|---|
| カレンダー | 共通りそなの記帳。日付タップで明細と手入力。上部に「今月使えるお金」、下に「入れる額」 |
| 未分類 | デビットの明細をカテゴリに振り分ける。店名ルールが育つ |
| 貯蓄 | 貯蓄の残りと年間支出の使用状況／運用資産の累計 |
| グラフ | カテゴリ別（月・年）と直近12か月の推移 |
| 設定 | 予算・自動計上・店名ルール・取込のオンオフ |

カレンダーと未分類には「**りそなを読み込む**」ボタンがあります。1時間ごとの自動取込を待たずに反映できます。
何回押しても無料枠には影響しません（1日100回でもGASの実行時間は数分、上限は90分/日）。

### 通知

使いすぎや入金日を、アプリ内（カレンダー上部の赤い帯と 🔔）と LINE のグループに知らせます。

- ペースが早い／変動費が予算の80%・100%／カテゴリごとのオーバー／使えるお金が2万円を切った／貯蓄がマイナス／24日20時に明日の入金額
- 同じ通知は1つの期間（25日〜翌月24日）に1回だけ。既読は2人それぞれ
- 夜23時〜朝7時はLINEに送らず、朝にまとめる（設定で変更可）
- 基準の数字は設定 → 通知 から変えられる
- LINEの準備は `やること.md` の 5

## 金額が変わったとき

**設定タブから変えます。SQLは不要です。**

- **予算**（家賃・食費・拠出など）: 金額と「いつから」を選ぶ。拠出や家賃のように自動で記帳される項目は、記帳される額も一緒に変わります
- **自動計上**: 名前・金額・記帳する日・土日祝のときのずらし方（そのまま／翌営業日／前営業日）を変えられる。日は「末日」も選べます（2月は28日、4月は30日に合わせる）

どちらも、選んだ月より前の記帳はそのまま残ります。**未来の月を選べば予約**になるので、昇給・引越し・育休も決まった時点で登録しておけば、その月から自動で切り替わります。

## ゼロから作り直す場合

| 順 | 場所 | 内容 |
|---|---|---|
| 1 | Supabase SQL Editor | `sql/v2_00_reset.sql` → `v2_01_schema.sql` → `v2_02_seed.sql` → `v2_03_extras.sql` → `v3_final.sql` → `v3_1_cycle.sql` → `v3_2_birthday_fix.sql` → `v3_3_alerts.sql` |
| 2 | Supabase Authentication | Create new user で2人分（**Auto Confirm User をオン**）。Sign In / Providers で新規登録をオフ |
| 3 | Supabase SQL Editor | users テーブルに auth_user_id を紐づける（下記） |
| 4 | Apps Script | `gas/resona_to_supabase.gs` を貼り、スクリプトプロパティ4つ、`setup`、ウェブアプリとしてデプロイ |
| 5 | Vercel | GitHubからインポート。環境変数4つ（下記） |
| 6 | iPhone | **Safari**で開いて共有 → ホーム画面に追加 |

```sql
update users set auth_user_id = (select id from auth.users where email = 'りほのアドレス') where name = 'りほ';
update users set auth_user_id = (select id from auth.users where email = 'ゆうきのアドレス') where name = 'ゆうき';
```

**Vercel の環境変数**

| Key | Value | Type |
|---|---|---|
| `NEXT_PUBLIC_SUPABASE_URL` | `https://xxxx.supabase.co`（`/rest/v1/` は付けない） | Config |
| `NEXT_PUBLIC_SUPABASE_ANON_KEY` | Publishable key（`sb_publishable_...`） | Config |
| `GAS_REFRESH_URL` | GASウェブアプリの `/exec` URL | Secret |
| `GAS_REFRESH_TOKEN` | GASの `REFRESH_TOKEN` と同じ文字列 | Secret |

Secret key（`sb_secret_...`）はVercelには入れません。GASのスクリプトプロパティにだけ置きます。

## 困ったとき

**Supabaseが一時停止した**
無料プランは7日間アクセスがないと止まります。Resume project で戻ります。データは消えません。
GASが1時間ごとにアクセスするので、普段は止まりません。

**明細が入ってこない**
GASで `checkMissing` を実行すると、Gmailにあるのに入っていないものが一覧で出ます。そのあと `importResona` を実行。

**取込エラーのメールが来た**
りそなのメールの書式が変わった可能性があります。同じメールについての通知は1回だけです。

**「りそなを読み込む」でエラー**
- 「設定がされていません」→ Vercelの `GAS_REFRESH_URL` / `GAS_REFRESH_TOKEN` が未登録、または登録後に再デプロイしていない
- 「合言葉が一致しません」→ GASの `REFRESH_TOKEN` と Vercel の `GAS_REFRESH_TOKEN` が違う
- 「正しい応答がありません」→ GASのデプロイで「アクセスできるユーザー」が「全員」になっていない
- GASのコードを書き換えたあとは「デプロイを管理」→ 鉛筆 → バージョン「新バージョン」でデプロイし直す（URLは変わりません）

**アプリが古いまま**
アプリを完全に閉じて開き直す。PCなら Ctrl+Shift+R。

## 設計上の判断

**口座を1つにした** — 貯蓄用の口座を分けると、どちらにいくらあるか把握しにくい。1つにまとめてアプリで分ける。弱点は「残高＝使える額ではない」ことなので、アプリの数字を見る運用が前提。

**貯蓄額を固定値で持たない** — 「毎月10万」を設定値で持つと、金額を変えたときに過去の月まで新しい金額で計算されてしまう。拠出と予算はどちらも期間つきで持っているので、その差から月ごとに出す。

**取り込み済みの判定をGmailのメッセージIDで行う** — りそなの承認番号は6桁で、いずれ別の取引と重なる。またGmailは同じ件名の通知を1スレッドにまとめるので、スレッド単位で判定すると後から届いた通知を取りこぼす。

**取り込む件名を限定する** — 「お取引不能のご連絡」には、決済が成立していないのに「ご利用金額」が書かれている。

**返金はマイナス金額で登録する** — 同じカテゴリの中で自然に相殺される。

**アプリで消した明細は再取込しない** — 消したことを記録しておき、GASがそのメールを飛ばす。

**カテゴリの自動判定にAIを使わない** — 店名の部分一致ルールを貯める。従量課金がなく、間違いは1行消せば直る。
